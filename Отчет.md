# Стек мониторинга и логирования

В проекте используется следующий стек:

- **Kubernetes** — среда запуска приложения и сервисов;
- **FastAPI** — backend-приложение;
- **PostgreSQL** — база данных приложения;
- **VictoriaMetrics** — сбор, хранение и запросы временных рядов;
- **PostgreSQL Exporter** — экспорт технических метрик PostgreSQL;
- **Vector** — сбор логов Kubernetes;
- **VictoriaLogs** — хранение и поиск логов;
- **Helm** — установка VictoriaMetrics, VictoriaLogs и Vector.

## Сбор метрик backend-приложения

FastAPI предоставляет метрики на endpoint:

```text
/metrics
```

Для автоматических HTTP-метрик используется библиотека
`prometheus-fastapi-instrumentator`, а бизнес-метрики создаются с помощью
`prometheus-client`.

VictoriaMetrics обнаруживает Pod'ы через Kubernetes service discovery. Для этого
к Pod'ам добавлены аннотации:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "8000"
prometheus.io/path: "/metrics"
```

## PostgreSQL Exporter

`postgres_exporter` подключается к PostgreSQL, собирает техническую статистику
базы данных и предоставляет её на endpoint `/metrics`.

VictoriaMetrics периодически забирает эти метрики через scrape.

Примеры метрик PostgreSQL:

- `pg_up` — доступность PostgreSQL;
- `pg_stat_database_numbackends` — количество подключений к базе;
- `pg_stat_database_xact_commit` — количество успешных транзакций;
- `pg_stat_database_xact_rollback` — количество отменённых транзакций;
- `pg_database_size_bytes` — размер базы данных.

Для PostgreSQL Exporter используются аннотации:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "9187"
prometheus.io/path: "/metrics"
```

## Схема сбора метрик и логов

```text
FastAPI /metrics ───────────────┐
                                ├──> VictoriaMetrics
PostgreSQL Exporter /metrics ───┘

Kubernetes logs ──> Vector ──> VictoriaLogs
```

## Реализованные бизнес-метрики

Бизнес-метрики относятся к доменной области заказов приложения My Eats.

| Метрика | Описание |
|---|---|
| `my_eats_orders_created_total` | Общее количество успешно созданных заказов. |
| `my_eats_orders_revenue_total` | Общая сумма оформленных заказов. |
| `my_eats_order_creation_errors_total{reason}` | Количество неудачных попыток создания заказов с указанием причины ошибки. |
| `my_eats_order_status_changes_total{from_status,to_status}` | Количество переходов заказов между статусами, например из `CREATED` в `COOKING`. |

### Причины ошибок создания заказа

Метрика `my_eats_order_creation_errors_total` использует label `reason`.
В проекте отслеживаются следующие причины:

- `items_not_found` — некоторые блюда не найдены;
- `items_unavailable` — некоторые блюда недоступны.

### Статусы заказа

Метрика `my_eats_order_status_changes_total` использует labels
`from_status` и `to_status`. Возможные статусы заказа:

- `CREATED`;
- `COOKING`;
- `DELIVERING`;
- `COMPLETED`;
- `CANCELLED`.
