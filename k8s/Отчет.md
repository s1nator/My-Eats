# Отчёт 

## 1. Использованные абстракции Kubernetes

В проекте используются следующие Kubernetes-ресурсы:

| Компонент | Использованные ресурсы | Назначение |
|---|---|---|
| **Backend** | `Deployment`, `Service`, `Secret` | Запуск двух экземпляров backend-приложения, предоставление внутреннего сетевого доступа и хранение строки подключения к базе данных |
| **Frontend** | `Deployment`, `Service`, `Gateway`, `HTTPRoute` | Запуск frontend-приложения, публикация его через внутренний Service и маршрутизация внешнего HTTP-трафика |
| **Database** | `StatefulSet`, `Service`, `Secret`, `Job` | Запуск PostgreSQL с постоянным хранилищем, предоставление доступа к базе, хранение параметров подключения и выполнение миграций |

### Дополнительные ресурсы

`ReplicaSet` отдельно в манифестах не описывается. Он создаётся автоматически ресурсом `Deployment` для поддержания нужного количества Pod'ов. `StatefulSet` управляет Pod'ами самостоятельно и ReplicaSet не создаёт.

### Gateway API

Для внешней маршрутизации используются два ресурса Gateway API:

- **`Gateway`** — точка входа для HTTP-трафика на порту `80`;
- **`HTTPRoute`** — правила распределения запросов между frontend и backend.

## 2. Взаимодействие сервисов приложения

Сервисы взаимодействуют внутри кластера через Kubernetes `Service`. Это позволяет обращаться к приложениям по стабильным DNS-именам, не используя напрямую IP-адреса Pod'ов.

### Общая схема

```text
Клиент
   |
   | HTTP :80
   v
Gateway: app-gateway
   |
   |-- /api/* --> backend-service:8000 --> Backend Pod'ы
   |
   `-- /* -----> frontend-service:80 --> Frontend Pod'ы
                                      |
                                      `-- запросы /api/* --> backend-service:8000

Backend Pod'ы
   |
   | DATABASE_URL
   v
db-service:5432
   |
   v
PostgreSQL Pod
```

### Маршрутизация через Gateway API

Ресурс `Gateway` с именем `app-gateway` принимает внешний HTTP-трафик на порту `80`.

Ресурс `HTTPRoute` направляет запросы по префиксу URL:

| URL запроса | Целевой Service | Назначение |
|---|---|---|
| `/api/*` | `backend-service:8000` | REST API backend-приложения |
| `/*` | `frontend-service:80` | Frontend-приложение и статические файлы |

Например, запрос:

```text
GET http://<адрес-gateway>/api/v1/menu
```

передаётся непосредственно в `backend-service` на порт `8000`.

Запрос к корневому адресу:

```text
GET http://<адрес-gateway>/
```

попадает в `frontend-service` на порт `80`.

### Взаимодействие с backend

`backend-service` имеет тип `ClusterIP` и доступен только внутри Kubernetes-кластера. Он выбирает Pod'ы backend по label `app: backend-1` и распределяет между ними запросы.

Backend-приложение запускается в двух экземплярах, поэтому Service выполняет балансировку трафика между двумя Pod'ами.

### Взаимодействие с frontend

`frontend-service` также имеет тип `ClusterIP` и направляет запросы в frontend Pod'ы по label `app: frontend-1`.

Frontend отправляет API-запросы по относительному пути `/api/...`. Поэтому при обращении пользователя к приложению запрос снова проходит через тот же Gateway и по правилу `/api/*` направляется в backend.

### Подключение backend к PostgreSQL

Backend подключается к PostgreSQL через Service `db-service` по адресу:

```text
db-service:5432
```

Строка подключения передаётся в backend через Kubernetes `Secret`. Благодаря этому backend обращается к базе по стабильному DNS-имени Service, а не по адресу конкретного Pod'а.

PostgreSQL запускается в `StatefulSet` и использует постоянное хранилище. Service базы является headless-сервисом (`clusterIP: None`).

### Выполнение миграций

Отдельный Kubernetes `Job` выполняет миграции базы данных:

```text
backend-migration-job
   |
   | ожидает готовности PostgreSQL через pg_isready
   v
db-service:5432
   |
   v
PostgreSQL
```

После готовности базы Job выполняет команды:

```text
alembic upgrade head
python seed.py
```

Таким образом, и backend, и Job миграций используют один и тот же Kubernetes Service `db-service` для подключения к PostgreSQL.

## 3. Итог

Внешний пользователь взаимодействует с приложением через `Gateway`. `HTTPRoute` разделяет запросы на frontend и backend. Внутри кластера frontend, backend и PostgreSQL взаимодействуют через Kubernetes Services, а конфиденциальные параметры подключения хранятся в Secrets.
